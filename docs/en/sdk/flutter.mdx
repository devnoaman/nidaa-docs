# nidaa_flutter

Registers device tokens, binds users, and posts open receipts. **It never sends messages** — sending (`messages:send`) is server-side only.

## Nidaa ≠ Firebase | نِداء مو Firebase

The package has **zero Firebase dependencies**. Wiring is two things: **your SDK key** + **the push token you supply**.

Token type must match how the engine sends for that platform:

- **Android:** FCM registration token.
- **iOS:** either the **raw APNs hex token** (engine sends directly via `.p8`) or an FCM token if your engine sends iOS through FCM.

## Install

```yaml
dependencies:
  nidaa_flutter:
    path: ../nidaa_flutter
```

## Initialize & register

```dart
// 1) Configure Nidaa. No network, no Firebase. Just your SDK key.
await Nidaa.initialize(
  baseUrl: 'http://127.0.0.1:8080', // engine root, no /v1
  apiKey: const String.fromEnvironment('NIDAA_SDK_KEY'), // devices:write ONLY
  userId: currentUser?.id, // optional
  debug: true,
);

// 2) YOUR APP gets a push token, however it chooses (pseudocode):
final String token = await myApp.getPushToken();

// 3) Hand it to Nidaa. platform is detected automatically (android/ios).
await Nidaa.registerDevice(token: token);

// When your app sees a new token:
myApp.onPushTokenRefresh((t) => Nidaa.updateToken(t));
```

<Info>`Nidaa.initialize` never talks to Firebase or APNs. The `nidaa_flutter` package has **zero Firebase dependencies**. Getting the token is your host app's job.</Info>

### Android: FCM token (Firebase is an optional host-app dependency)

On Android the token must be an FCM registration token. One common way is to add `firebase_messaging` to **your app's** `pubspec.yaml` (not part of the Nidaa SDK):

```dart
// In YOUR app, using YOUR optional firebase_messaging dependency:
final token = await FirebaseMessaging.instance.getToken();
if (token != null) await Nidaa.registerDevice(token: token);
FirebaseMessaging.instance.onTokenRefresh.listen(Nidaa.updateToken);
```

### iOS path B: raw APNs hex token (no Firebase)

When the engine sends iOS directly over APNs (`.p8`), register the **raw APNs device token as a hex string**. Get it natively, e.g. from `didRegisterForRemoteNotificationsWithDeviceToken` exposed through your own `MethodChannel`:

```dart
// YOUR app's platform channel (pseudocode). No Firebase involved.
const channel = MethodChannel('myapp/apns');
final String apnsHex = await channel.invokeMethod('getAPNSToken');
await Nidaa.registerDevice(token: apnsHex);
```

## Forward messages and opens

The SDK doesn't listen to pushes itself. Your app forwards what it receives, from whatever push plugin it uses:

```dart
// Pseudocode: call these from YOUR app's push handlers.
void onForegroundPush(Map<String, dynamic> data, {String? title, String? body}) =>
    Nidaa.handleMessage(NidaaMessage.fromData(data, title: title, body: body));

void onNotificationTapped(Map<String, dynamic> data) =>
    Nidaa.handleOpen(NidaaMessage.fromData(data)); // also for the launch message

Nidaa.onMessage.listen((m) => print('foreground: ${m.title}'));
Nidaa.onOpen.listen((m) => router.go(m.deepLink ?? '/'));
```

Open receipts need the message id in the push data as `nidaa_message_id` (or `message_id`).

## Topics, users, opt-out

```dart
await Nidaa.subscribeToTopic('news');
await Nidaa.setUserId('u_123'); // after login
await Nidaa.clearUserId();      // on logout
await Nidaa.unregister();       // opt-out
```

## SDK ↔ REST

| SDK | REST |
| --- | --- |
| `initialize` | — (config only, no network) |
| `registerDevice(token:)` / `updateToken(t)` / auto re-sync | `POST /v1/devices` (exponential backoff) |
| `setUserId(id)` / `clearUserId()` | `PATCH /v1/devices/{token}` `{"user_id": id \| null}` |
| `unregister()` | `DELETE /v1/devices/{token}` |
| `subscribeToTopic` / `unsubscribeFromTopic` / `listTopics` | `PUT` / `DELETE` / `GET /v1/devices/{token}/topics[/{topic}]` |
| `handleMessage(m)` → `onMessage` | — (local stream) |
| `handleOpen(m)` → `onOpen` | `POST /v1/messages/{id}/opens` (once per id) |

<Warning>Never put a `messages:send` key in an app. لا تضع مفتاح `messages:send` داخل التطبيق أبداً.</Warning>
