# نِداء | Nidaa

نِداء منصة إشعارات Push (SaaS) مصممة **للعراق أولاً**. يتعامل المطوّر مع نِداء عبر:

- **REST API** (`/v1`): ترسل الرسائل من الخادم (backend) الخاص بك.
- **Flutter SDK** (`nidaa_flutter`): يسجّل توكنات الأجهزة، ويربط المستخدمين، ويبلّغ عن فتح الإشعارات.
- **لوحة التحكم**: لإدارة التطبيقات والمفاتيح وبيانات المزوّدين وإرسال الإشعارات.

## التوصيل الفعلي

نِداء لا يستبدل شبكات Apple وGoogle. **المرحلة الأخيرة من التوصيل تبقى عبر APNs (iOS) وFCM (أندرويد)**. محرّك نِداء يحفظ بيانات المزوّد الخاصة بك ويتواصل مع APNs/FCM نيابةً عنك. أنت لا ترسل من لوحة Firebase أبداً.

## لا يعتمد الـ SDK على Firebase

حزمة Flutter **لا تحتوي على أي اعتماد على Firebase** (لا `firebase_core` ولا `firebase_messaging`). لا تطلب الأذونات، ولا تجلب التوكن، ولا تستقبل الإشعارات بنفسها. تطبيقك يجلب التوكن بالطريقة التي يختارها، ثم يمرّره إلى `Nidaa.registerDevice(token: ...)`.

## هيكل الحسابات

<div dir="ltr">

```
org ──< app ──< environment (dev | prod) ──< api_key
                                         ├──< provider_credential (apns | fcm)
                                         ├──< device
                                         └──< message ──< message_delivery
```

</div>

البيئتان `dev` و`prod` منفصلتان تماماً (الأجهزة، الرسائل، بيانات المزوّد، المفاتيح).

## المصادقة

أرسل المفتاح بهذا الشكل: `Authorization: Bearer <api_key>` **أو** `X-Nidaa-Key: <api_key>`. المفتاح يحدد المؤسسة والتطبيق والبيئة.

صيغة المفتاح: `nd_live_…` (prod) و`nd_test_…` (dev).

| الصلاحية (Scope) | يستخدمها | تسمح بـ |
| --- | --- | --- |
| `devices:write` | Flutter SDK (مفتاح العميل) | تسجيل الجهاز وتحديثه وإلغاؤه، وإيصالات الفتح |
| `messages:send` | الخادم الخاص بك (مفتاح الخادم) | `POST /v1/messages` |
| `messages:read` | الخادم الخاص بك | `GET /v1/messages/{id}` |

<Warning>مفتاح الـ SDK يجب ألا يحمل صلاحية `messages:send` أبداً، لأنه موجود داخل التطبيق.</Warning>

## عنوان الخادم (Base URL)

عنوان الإنتاج **لم يُحدَّد بعد (TBD)**. للتطوير المحلي، جذر المحرّك هو `http://127.0.0.1:8080`، وكل المسارات تحت `/v1`.
